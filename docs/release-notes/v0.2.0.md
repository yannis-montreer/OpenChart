OpenChart 0.2.0 adds indicators you can write yourself, more built-in indicators, more
drawing tools, and settings that keep the disk from filling up. It is still a pre-release.

**Your broker tokens stay on your own machine:** in the Windows Credential Manager, or for
the Windows service and Docker in an encrypted file in the data folder, with its key kept
apart. OpenChart sends them only to your broker (and the Telegram token only to Telegram).
Your own indicator files run in an isolated worker that has no access to them.

**Not financial advice. Use at your own risk. No warranty.** Alerts can be late or missed
(network loss, broker outages, bugs). Provided "as is" under the Apache License 2.0.

**Downloads:** `OpenChart-Server` (the server and its Windows service scripts; see the
README Quickstart) and `OpenChart-Viewer` (a desktop window for the chart). The `.exe`
files are not signed, so Windows SmartScreen warns on first launch: choose "More info",
then "Run anyway". SHA-256 sums are in `SHA256SUMS.txt`.

## What's new

- **Custom indicators.** Write an indicator as a Python file and see it on the chart.
  - **The browser editor:** create, edit, test and delete your indicator files in the
    Indicators menu. It needs the Windows service install or Docker compose, and a setting
    only the server's PC can change (see "Custom indicators: where the editor works").
  - **An isolated worker:** your files run in a separate worker process with no access to
    the data folder, the database, the tokens or the network. The server keeps drawing
    prices and sending alerts even if a script hangs.
  - **The `ta` helper library:** 34 helpers (moving averages, oscillators, volatility,
    pivots, windows) defined as TradingView defines them, each tested not to look ahead.
    The guide is `docs/indicators.md`.
  - **Save-time checks:** when you save a file, OpenChart warns if it looks ahead at bars
    that do not exist yet, or if its warmup looks too short. The checks warn; they never block.
- **Built-in indicators:** SMA, RSI, MACD, Bollinger Bands, ATR, Stochastic and tick volume,
  next to EMA. Each has its own settings and legend row.
- **New output kinds** for indicators: histograms, areas, fills between lines, levels,
  markers and background colours, plus text inputs.
- **Indicators are stored per chart on the server,** so every browser shows the same ones.
  Layouts save and load them. You can import an indicator file from the menu.
- **Six new drawing tools:** vertical line, rectangle, channel, Fibonacci, text and measure.
  Undo, lock, hide, and a list panel of all drawings. Alerts still work on the horizontal
  line, trendline, ray and extended line only.
- **The forming bar** is drawn on the chart and used by indicators, so an indicator moves
  with the live price.
- **Retention settings:** raw ticks (Settings, Data & time) are kept 7 days, 30 days (the
  default), 90 days, 1 year or forever, or not stored; minute history per instrument
  (Settings, Your instruments) is kept 3 months, 1 year or 2 years (the default). The server deletes what is older once a
  day. `openchart retention` shows what the next run would delete, `openchart purge`
  reclaims the space, hourly and longer bars are never deleted, and the service logs are
  rotated.
- **A bar cache** makes charts and indicators on long histories load faster.
- Fixes and hardening after a security review of the editor, and many smaller fixes.

## Custom indicators: where the editor works

| Install | Your indicator files | Browser editor |
|---|---|---|
| Windows service (release zip, installer run) | run in the isolated worker | available once switched on |
| Docker with `docker-compose.yml` | run in the `indicator-worker` container | available once switched on |
| Source install (`openchart run`) | run in a weaker mode (a restricted process, with a notice in the Indicators menu) | **off, by design** |

A source install cannot isolate your files from your tokens and data, so the editor stays
off there and the setting cannot override that. You can still put indicator files in the
`indicators` folder of the data folder, and they run: only use files you trust.

**To turn editing on** (service or Docker compose), run this on the server's own PC:

    openchart settings set indicator-editing on

(for the service add `--data-dir C:\ProgramData\OpenChart\data`; for Docker run it inside
the container: `docker compose exec openchart openchart settings set indicator-editing on`).
It takes effect on the next request, without a restart. `off` turns it off again. No web
page or API can change this setting. With it on, every browser that is logged in may edit,
the phone included; turn it off when you do not need it.

## Known limits

- **OANDA only,** and one server per OANDA account (about two price streams per practice
  account).
- **Indicators:** no alerts on indicators, and no indicators from another timeframe.
  A few `ta` details were inferred from TradingView's documentation and not all are checked
  against it (`pivotlow` ties, `rising` and `falling` for n other than 2).
- **Custom indicator code is code:** treat a file like a program you run. On a source
  install it can read your files and use the network.
- **The save-time checks can miss things;** they warn and never prove a file is safe to
  trade on.
- **Drawings:** alerts on the new tools (Fibonacci, channel, rectangle, vertical line) are
  not built. A lock guards against accidents in your browser: the server stores it but
  does not enforce it, so a script or an undo can still change a locked drawing.
- **Retention deletes data.** The 30-day default for ticks and 2 years for minutes applies
  to existing installs too (see below). Choose "Forever" in Settings first if you want to
  keep more.
- **Not included:** 5-second candles, bar replay, backtesting, a Linux service script (use
  Docker), automatic updates. The Docker image is not published: build it from the
  repository. The README screenshot of the chart predates the new drawing tools.
- **The phone is for reading the chart;** drawing works best with a mouse.

## Updating from 0.1.0

**Before updating, back up the data folder.** The first start of 0.2.0 upgrades the
database, and 0.1.0 cannot read it afterwards. Going back means restoring the backup
together with 0.1.0.

**What the first start does.** It applies two small migrations, in order:

| Migration | What | Merged in |
|---|---|---|
| 0008 `chart_indicators` | a new table for the indicators of each chart | #33 (CI-3 backend) |
| 0009 `m1_depth` | a new column for the minute history of each instrument | #50 (storage step 2) |

0009 is the newest migration in this release; nothing comes after it. Neither rewrites your
candles (0008 adds a table, 0009 a column). The log shows each as `database migration
000N ... applied`, with its time. If a migration cannot finish, it changes nothing and the
log says why.

**Retention, on the first start:** the server notes the time and, for 24 hours, deletes
nothing; it only logs what it would delete. Then it removes ticks older than 30 days and
minutes older than 2 years (your defaults), once a day. Run `openchart retention` to see
the list, and choose other limits in Settings before the 24 hours are up.

**Windows service (release zip):**
1. Back up: `openchart.exe backup --data-dir C:\ProgramData\OpenChart\data`.
2. Extract the new server zip to a new folder and run its `install-service.cmd`. It stops
   the running service, upgrades the database, points the service at the new version and
   starts it. Your data, settings and tokens stay. The installer also sets up the indicator
   sandbox.
3. Check `C:\ProgramData\OpenChart\data\logs\service.log`: it shows migrations 0008 and
   0009 applied, `indicator sandbox: ready (AppContainer)` and the feed connecting. Then
   delete the old folder.
4. Optional: `openchart settings set indicator-editing on` (see above).

**From a source checkout:**
1. Stop the server.
2. Copy the data folder.
3. `git pull` (or check out the `v0.2.0` tag), then `pip install -e .` if the
   dependencies changed.
4. Run `openchart migrate`.
5. Compare `openchart stats` before and after: the counts must be equal.
6. Start the server. The browser editor is off on a source install.

**Docker:**
1. Back up: `docker compose exec openchart openchart backup`.
2. Then `docker compose build` and `docker compose up -d`. The upgrade runs at start, and
   the compose file now also starts the `indicator-worker` container.
