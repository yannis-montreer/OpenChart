OpenChart 0.1.0 is the first release: a self-hosted chart and alert server for OANDA, for an
always-on Windows PC (or Docker), with a web chart and a desktop viewer.

**Downloads:** `OpenChart-Server` (the server and its Windows service scripts; see the
README Quickstart) and `OpenChart-Viewer` (a desktop window for the chart). The `.exe`
files are not signed, so Windows SmartScreen warns on first launch: choose "More info",
then "Run anyway". SHA-256 sums are in `SHA256SUMS.txt`.

## What works

- **Broker:** OANDA (practice and live). It downloads history: two years of minute bars by
  default, plus hourly bars as far back as OANDA has them (gold: March 2006). History
  downloads newest first and resumes after an interruption. A live price stream
  reconnects by itself and fills any gap.
- **Chart in the browser:** every timeframe from 1 second to 1 week. 4h, daily and weekly
  bars follow the 17:00 New York trading day (checked equal to OANDA's own candles).
  Also: mid, bid and ask prices, history that loads as you scroll back, a crosshair
  legend, Bid/Ask lines with a bar countdown, a dark and a light theme, a watchlist, a
  screenshot button, and full screen. Readable on a phone.
- **Instruments:** add any OANDA instrument in Settings. Each uses its own decimals and
  trading hours.
- **Drawings:** horizontal line, trendline, ray and extended line, with a magnet (hold
  Ctrl). They are stored on the server and shared by every open browser.
- **Alerts:** on lines (sloped ones too) and price levels: crossing, up or down; once,
  once per bar, on bar close, or at most once a minute. They are evaluated in the server
  and sent to Telegram and to open browsers. Minutes missed while the PC slept or the feed
  dropped are checked afterwards, and those alerts arrive marked as late. Telegram also
  reports when the engine starts and when the feed stalls or recovers.
- **Indicators:** EMA. Each has its own settings and legend row. You can add your own as
  Python files in the data folder's `indicators` folder.
- **Chart types:** candles, bars, line, area and Heikin Ashi.
- **Layouts:** save and load named layouts, with a starred one that loads on start.
- **Setup and security:** a setup page on first start, and a single password (argon2,
  rate-limited login). Tokens are kept in the Windows Credential Manager, or for the
  service and Docker in an encrypted file whose key is kept apart. The API never returns
  them.
- **Windows service:** `install-service.cmd` installs it with NSSM. It starts on boot,
  restarts on failure, and logs to the data folder. A firewall rule limits it to
  Tailscale addresses.
- **Docker:** `docker-compose.yml` (build the image yourself).
- **Backups:** `openchart backup` writes one zip of the data folder, safe while the server
  runs.
- **Desktop viewer:** OpenChart Viewer opens the chart in its own window, on this PC or
  over Tailscale.

### Since the first milestones, worth knowing

- **Stored history matches OANDA's candles.** Minutes built from the live stream are
  replaced by OANDA's own candles: once a minute for the last 15 minutes; the hour before
  every stop, reconnect or sleep; and the whole previous day once a day. That is two
  extra requests per instrument at start and one per instrument per day.
- **The database is 57% smaller:** candle prices are stored as exact integers. The upgrade
  happens by itself on first start (see "Updating" below).
- **One process at a time writes to a data folder.** A second server refuses to start.
  `migrate`, `backfill`, `repair`, `purge`, `reset-password` and `secrets to-file`
  refuse while the server runs (exit code 4: stop it first). `stats`, `gaps` and
  `backup` run beside it.
- **A changed secret key stops the server, with an explanation,** instead of running
  without its tokens. Docker shows it as restarting.
- **OANDA errors say what was refused,** and a token pasted wrongly (with spaces or
  control characters) is refused before any request is sent.

## Known limits

- **OANDA only.** Other brokers are planned (the provider interface is ready).
- **One server per OANDA account:** OANDA allows only about two price streams per
  practice account.
- **Minute charts (1m to 30m) go back as far as stored minute bars,** two years by
  default (`openchart backfill --years N` for more). Second charts only cover the times
  the server ran with tick storage on.
- **Indicators:** only EMA so far. No indicator alerts, and no indicators from another
  timeframe. Your own indicator files run inside the server process, so only use files
  you trust. Isolated custom indicators are being designed.
- **Disk:** tick files and minute bars are kept forever for now; retention settings are
  planned.
- **The phone is for reading the chart;** drawing works best with a mouse.
- **Not included:** backtesting, a Linux service script (use Docker), automatic
  updates. The Docker image is not published: build it from the repository.

## Updating

**Before updating, back up the data folder.** The first start of 0.1.0 upgrades the
database (integer prices, migration 0007), and an older version cannot read it
afterwards.

- **Free space:** it needs about 1.5 times the database free on the same disk.
- **Time:** about 16 s for a 380 MB database, which then shrinks to about 165 MB.
- **If it cannot finish,** for example an inexact price or too little space, it changes
  nothing and the log says why.

**Windows service (release zip):**
1. Back up: `openchart.exe backup --data-dir C:\ProgramData\OpenChart\data` (or copy the
   folder while the service is stopped).
2. Extract the new server zip to a new folder and run its `install-service.cmd`. It stops
   the running service before it touches the database, upgrades the database, points the
   service at the new version and starts it. Your data, settings and tokens stay.
3. Check the log `C:\ProgramData\OpenChart\data\logs\service.log`. It shows "database
   migration 0007 integer_prices applied" and the feed connecting. Then delete the old
   folder.

**From a source checkout:**
1. Stop the server.
2. Copy the data folder.
3. `git pull`.
4. Run `openchart migrate`.
5. Compare `openchart stats` before and after: the counts must be equal.
6. Start the server.

**Docker:**
1. Back up: `docker compose exec openchart openchart backup`.
2. Then `docker compose build` and `docker compose up -d`. The upgrade runs at start.

**Going back to an earlier version** means restoring the backup together with that
version.
